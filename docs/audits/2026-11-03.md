## 判断が要るもの（Kento へ）

> リポジトリは今は非公開です（2026-11-03 に、認証なしで GitHub に問い合わせると 404 でした。Quickstart の clone が通ったのは、この PC に保存されている認証情報を使ったためです）。A は**公開する前に**決める必要があります。

- **A. 勤務先の識別情報（公開する前に）**
  - 全コミットの作者メールが勤務先のアドレスです（`git log --format=%ae`）。
  - 文書には、勤務先の名前（BrightFlow の組織名、AWS プロファイル名 `brightflow-sandbox-ikeda`）も出てきます（CLAUDE.md、`.claude/hooks/guard-aws.sh`、`video/narration.ts`、how-we-built.md、deploy.md）。
  - 履歴を書き換えるかどうか（例: `git filter-repo --mailmap` で GitHub の noreply アドレスにする。force push が要る）と、勤務先の名前を残すかどうかを決めてください。
  - Claude からは、履歴の書き換えも force push もしていません。
- **B. 評価用20場面を、開発の途中の診断に使った**
  - D-022 で弟子を変えたきっかけは評価用の場面 E13、D-033 で浜風運輸の台帳を直したきっかけは E11 です。
  - Before と After は同じ台帳とモデルで測るので比べられますが、20場面は「一度も見ていない場面」ではなく、開発の途中に見た場面です。
  - **推奨:** README の結果の欄にそう書く（11/7 までに新しい評価用の場面を作り直すのは、時間と凍結の点で割に合わない）。
- **C. 沿革の質問の採点**
  - シミュレータの「わけ」は、隠しの沿革の短い文をそのまま返します。後任の答えは、その文に含まれる語で採点しています。
  - 一部の語（セキュリティ・規程・Zoom）は、公開されている台帳にも出てきます。
  - **推奨:** README に「沿革の質問の正答は、師匠の言葉が心得帳を通って後任まで届いたかを見るもので、言い換えへの強さは測っていない」と書く。
- **D. 師匠に回すことを、コードでも必ず守る**
  - 今は「値引き・契約が絡むなら師匠に回す」をモデルが判断しています（評価では 9/9 回しました）。
  - 案を作ったあとに、次の2つをコードで行えば、ハードルール（HITL）がモデルの判断に頼らなくなります。
    - 場面の種類が T3（見積り・金額）か、文面に値引・契約・条件が出てきたら、師匠に回す（`escalateToMaster=true`）。
    - 心得が「師匠に回さない」に変える直し（`escalateToMaster=false`）を受け付けない。
  - 数字が変わりうるので、入れるなら 11/7 の正式計測の**前**にしてください。**推奨: 入れる。**
- **E. 確かめ稽古で × が付いても、心得は残る**
  - 直した場面を新しい心得で解き直した案に、師匠が △／× を付けても、心得はそのまま有効です。今は、その印が記録されて回帰の確認に進むだけです。
  - 差し戻すか、範囲を絞るかを決めてください（D-028／D-037 の設計の範囲）。
- **F. キックオフ前のデータの書き方**
  - README の「事前に用意した架空のサンプルデータを、期間中にデータファイルとして作成」と、evolution.md の「キックオフ前にコードもデータも作っていない」を、一つの言い方にそろえたいです。
  - **案:** 「架空の世界の設計はキックオフ前の計画メモにあり、データファイルはすべて期間中に書いた」。
- **G. 公開デモの URL**
  - README は「11/6 に追記」のままですが、公開版はすでに動いています（D-035・D-039）。今載せるかどうかを決めてください。
- **H. 51.2% の後ろの一節**
  - 「後継ぎは、何年も見てきた家族より、従業員や買い手であることが増えている」には出典がありません。
  - 出典を足すか、この一節を削るかを決めてください（51.2% には帝国データバンクの出典があります）。
- **I. 動画 s08b の対比が弱い**

  - 11/7 に撮るとき、質問をはっきりさせて撮り直すか、根拠の行（K-011／K-018）を大きく見せるかを決めてください。
- **J. 費用の上限を少し超えうる**
  - 1回の予約から、確かめ稽古と回帰の確認の呼び出しが最大5回ほどに広がります。上限に当たったかは使った額を記録する前に調べ、カウンタの読み書きにも鍵がありません。
  - そのため、同時に多くの人が使うと `KOKOROE_DAILY_USD` を少し超えることがあります。
  - Console のワークスペースの月の上限が最後の止め役なので、**推奨: 今は受け入れ、上限を上げる（$10）ときに8割で止めるようにする。**
  - `KOKOROE_STORE=memory` のときの Memory Store の呼び出しは、上限の数に入りません（運用者が明示的に有効にしたときだけ）。
