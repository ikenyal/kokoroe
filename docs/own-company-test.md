# 自分の会社での比較テストの手順（D-060、所要 40〜60 分）

作者（Kento）が、**実際に経験のある取引先**について、同じ作法を「文章で書く」時間と「○△× で判定する」時間を比べ、出てくる作法の数を
数えるテストです。師匠役テスト（架空の会社、D-059）では、作者に経験がないため文章の課題が成り立ちませんでした。その続きです。

- **どこで:** 手元の PC だけ。`npm run own`（127.0.0.1 の開発用サーバー）。公開版にはこのモードはありません。
- **費用:** 案・読み取りで数十セント。上限は $2。
- **repo に残るもの:** 時間と件数だけ（`docs/results/own-company-test-<日付>.json`）。場面・文章・取引先の名前・心得の文は、
  `~/.kokoroe` から出ません。保存の前に、文字列が入っていないことをコードとテストで確かめています。

## 0. 書き方の注意（機密を送らないために）

Claude API に送られるもの（案・読み取り・回答を作るとき）:
- 台帳の項目（会社名、取引先名・窓口・決裁者・制約など）
- あなたが書く場面の文
- 判定に添える一言、「なぜ？」への答え、選んだ読み方
- それらから作られた心得の文。以後の案を作るたびに送られます。
- 暖簾を継ぐで聞いた質問（使った場合）

**送らないもの:** 比較テストで「文章で書く」欄の文は送りません（このPCの中だけで、時間と件数のためにだけ使います）。

- **名前は仮名にする:**
  - 取引先は「取引先A」〜「取引先E」。
  - 人は「窓口の課長」「先方の社長」のように役割で書く。
- **入れないもの:** 金額、契約条件、未発表の商品や計画、個人が分かる情報（名前・連絡先・個人の事情）。
- **一言と「なぜ？」にも同じ注意:** 判定のときの一言や「なぜ？」の答えに、実名・金額・人の事情が入りやすいので、ここでも仮名と一般的な書き方にします。
- **場面は一般的な書き方にする:**
  - 例：「大口の取引先に、納期が2週間遅れると伝える」「担当が替わったことを先方に知らせる」。
  - 社名・案件名・日付は書かない。
- **会社の規程:** 勤務先の情報を外部の API に送ってよいか、事前に確かめてください。迷う内容は書かない。

## 1. 準備（5分）

1. `.env.local` に `ANTHROPIC_API_KEY` があることを確かめる（中身は表示しない）。
2. ほかの開発用サーバーが止まっていることを確かめてから、`npm run own` で起動し、http://127.0.0.1:3000 を開く。
3. 「台帳」で会社と取引先を入れる。
   - 取引先は 5 社（取引先A〜E）。
   - 制約や繁忙月は、仮名でも差し支えない一般的な書き方で書く。

## 2. 比較テストを始める

帳場の「次の場面を書く」の下にある「比較テスト」を開き、「**比較テストを始める**」を押します。

- 始めると、文章を書いていない場面は、帳場で**案を作らずに待たせます**。AI の案を見る前に書くためです。
- 測る項目:
  - **状況を書く:** 場面を入力する時間。判定・文章とは別の行で、どちらにも含めません。
  - **文章で書く:** 書き始めてから「記録する」まで。
  - **○△× を付ける:** 案を読んでから印まで。
  - **一言・読み方の選択・「なぜ」・確かめ:** 師匠役テストと同じです。

## 3. 場面を5つ書く（各社1つ）

帳場の「次の場面を書く」で、取引先A〜E について1つずつ、実際によくある場面を書きます。

- 経験のある、引き継ぐときに迷いそうな場面を選びます。
- 1つ目を書くと「先に文章で書いてください」と出ます。そのまま5つ目まで、場面だけを書きます。

## 4. 先に文章で書く（5件）

「比較テスト」のページで場面を1つ選び、後任に引き継ぐつもりで作法を文章にして「記録する」。5件とも書きます。

- 誰に・何で・いつ・どう伝えるか。なぜそうするのかも。
- まだ AI の案は見ていません。案は、書き終わった場面から作られます。

## 5. 判定する（5件）

帳場に戻ると、書き終えた場面から順に弟子の案が出ます。いつもどおり ○／△／× と、あれば一言を付けます。

- 読み方の候補、「なぜ？」、確かめにも答えます。
- 弟子の読み取り（右の欄）がすべて終わるまで待ちます。

## 6. 作法を数える

「比較テスト」のまとめのページを開きます（帳場の「次の場面を書く」の下の「こちら」）。

- **基準はひとつ:** 「**後任がそのまま実行できる具体的な作法か**」。
- **文章で書いたもの:** それぞれに、基準に当たる作法がいくつ入っているかを数字で入れる。
- **判定から覚えた心得:** 基準に当たるものに印を付ける。
- 「数えた結果を残す」を押す。
- ページの下の「repo に保存されるもの」に、時間と件数だけが出ていることを目で確かめる。

## 7. 保存する（別のターミナルで）

```
npm run -s own:save     # → docs/results/own-company-test-<日付>.json（時間と件数だけ）
```

保存されたファイルを開き、文が入っていないことを確かめてから、Claude に「比較テストの結果を記録して」と伝えてください。

## 8. 片付け

1. 開発用サーバーを止める（Ctrl+C）。
2. もう一度 `npm run own` で起動し、「台帳」の下の「**全部消す**」に `消す` と入れて押す。
   - `~/.kokoroe` の、このモードが作ったファイルが消えます。
   - 弟子の読み取りが終わっていないと消せません。
3. サーバーを止める。`ls ~/.kokoroe` が「No such file or directory」になれば完了です。

## 結果の扱い（あらかじめ決めておくこと）

- 1人・5件の実測です。「作者1人が、自分の取引先5社（仮名）で測った範囲」と書きます。
- **「状況を書く」時間:** 判定の側にも文章の側にも含めません。実際の業務では、場面は取引先とのやり取りの中で自然に生じるためです。
- **作法の数:** 作者が同じ基準で数えたもので、他の人の確認はありません。
